This guide walks you through installing photo-cli, running your first `archive` command, and connecting the resulting archive to an AI assistant over MCP. By the end, you will have a `[year]/[month]/[day]/` folder of hash-stamped photos, a SQLite index, one album per country/city — and an MCP server that lets Claude or VS Code query it conversationally.

<Steps>
  <Step title="Install photo-cli">
    Follow the [Installation](/installation) guide, then verify:

    ```bash
    photo-cli --version
    ```
  </Step>
  <Step title="Run your first archive command">
    ```bash
    photo-cli archive \
      --input /path/to/source \
      --output /path/to/archive \
      --reverse-geocode OpenStreetMapFoundation \
      --openstreetmap-properties country city \
      --auto-reverse-geocode-album \
      --expected-day-range 7300
    ```

    | Argument | Effect |
    | -------- | ------ |
    | `--input` / `--output` | Source folder to read, archive folder to write |
    | `--reverse-geocode` + `--openstreetmap-properties` | Resolves each coordinate to a `country-city` address |
    | `--auto-reverse-geocode-album` | Creates one album per geocoded level (e.g., `Italia-Firenze`) |
    | `--expected-day-range 7300` | Safety net — aborts if photos span more than ~20 years |

    <Note>
      Source files are never modified. Add `--delete-on-source` only after you have verified the archive — it removes sources after copy verification passes.
    </Note>

    <Frame caption="Executing photo-cli archive in the macOS terminal">
      <img src="/images/screenshots/macos/execute.png" alt="photo-cli archive executing on macOS" />
    </Frame>
  </Step>
  <Step title="What happens behind the scenes">
    The `archive` command is built for long-term, incremental storage. In a single run it:

    1. **Discovers** every photo and [companion file](/configuration/companion-files) (Live Photo `.mov`, sidecar `.xmp`, `.aae`) under the source folder.
    2. **Reads EXIF** for the taken date and GPS coordinates of each photo.
    3. **Reverse-geocodes** the coordinates with [OpenStreetMap](/reverse-geocoding/providers), deduplicating repeated locations in memory so the rate-limited API is only called once per unique coordinate.
    4. **Guards the date range** — `--expected-day-range 7300` aborts the run if photos span more than ~20 years, catching a mis-pointed source folder before any copy.
    5. **Lays photos out** as `[year]/[month]/[day]/` derived from the EXIF date.
    6. **Embeds a SHA1** in every file name (`yyyy.MM.dd_HH.mm.ss-{sha1}.ext`); companion files share the SHA1 stem of their main photo.
    7. **Deduplicates automatically** — byte-identical files hash the same and only one copy is written.
    8. **Falls back** to a `no-photo-taken-date/` subfolder for photos missing a date.
    9. **Verifies the copy** by re-hashing every output file against its source.
    10. **Indexes everything** in `photo-cli.sqlite3` at the root of the archive — paths, dates, coordinates, formatted addresses, individual `Address1..Address8` levels, SHA1.
    11. **Builds albums** — `--auto-reverse-geocode-album` creates one album per geocoded level (`Italia`, `Italia-Firenze`, `Venezia`, `United Kingdom`, …) so you can later open every photo from a country or city without remembering exact dates.
  </Step>
  <Step title="Check the output">
    Open the archive folder. You will find photos laid out as `[year]/[month]/[day]/yyyy.MM.dd_HH.mm.ss-{sha1}.ext`, byte-for-byte duplicates skipped automatically, photos with no taken date in a `no-photo-taken-date/` subfolder, and a `photo-cli.sqlite3` database at the root indexing every photo, address, and album.

  </Step>
  <Step title="List or open archived photos">
    Query the SQLite index to open photos by date or list every album that was created:

    ```bash
    photo-cli list --input /path/to/archive --type PhotosByDate --year 2008 --month 10
    photo-cli list --input /path/to/archive --type Albums
    ```

    On macOS matches open in Preview; on Linux/Windows paths are printed to stdout.

    <Frame caption="photo-cli list opening the October 2008 photos in macOS Preview">
      <img src="/images/screenshots/macos/viewing-in-preview-app.png" alt="Photos from October 2008 opened in macOS Preview by photo-cli list" />
    </Frame>
  </Step>
  <Step title="Connect the archive to an AI assistant over MCP">
    `photo-cli mcp` starts a [Model Context Protocol](https://modelcontextprotocol.io/) stdio server that exposes the archive's SQLite database to AI assistants. Tools like Claude Code, Claude Desktop, and VS Code can then search by date, location, album, or proximity to a GPS coordinate — and even open matching photos in your default viewer. See the [mcp command reference](/commands/mcp) for the full tool list.

    **Claude Code (CLI):**

    ```bash
    claude mcp add photo-cli --scope user -- photo-cli mcp --input /path/to/archive
    ```

    **Claude Desktop** — add to `claude_desktop_config.json`:

    ```json
    "mcpServers": {
      "photo-cli": {
        "command": "/Users/{your-user}/.dotnet/tools/photo-cli",
        "args": ["mcp", "--input", "/Users/{your-user}/{archive-folder}"]
      }
    }
    ```

    **VS Code** — add to `.vscode/mcp.json` or your user settings:

    ```json
    "photo-cli": {
      "type": "stdio",
      "command": "/Users/{your-user}/.dotnet/tools/photo-cli",
      "args": ["mcp", "--input", "/Users/{your-user}/{archive-folder}"]
    }
    ```

    Once connected, ask the assistant things like *"how many photos do I have from Italy in 2008?"*, *"show me everything taken within 5 km of 43.78, 11.23"*, or *"open all photos in the Italia-Firenze album"*.
  </Step>
</Steps>
