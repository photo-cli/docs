photo-cli is a [CLI](https://en.wikipedia.org/wiki/Command-line_interface) tool (works on Linux, macOS, and Windows) that extracts when and where ([reverse geocode](https://en.wikipedia.org/wiki/Reverse_geocoding)) your photographs were taken, [archives](/commands/archive) or [copies](/commands/copy) them into a new organized folder (without modifying the source folder) with various [folder](/commands/copy) and [file naming](/commands/copy) strategies, with album support to categorize, [list and view](/commands/list) them easily. All photo metadata is stored in a local SQLite database for archive operations and CSV for others. From the [CSV](https://en.wikipedia.org/wiki/Comma-separated_values) file (viewable in Microsoft Excel, Libre/OpenOffice Calc, Apple Numbers, Google Sheets), you can [navigate your photo locations on Google Maps and Earth with your custom label and pin style](#5-navigate-your-photo-locations-on-google-maps-and-google-earth).

## What photo-cli does

Every photo taken by a modern camera or smartphone stores metadata directly in the image file using the [Exchangeable image file format (EXIF)](https://en.wikipedia.org/wiki/Exif). photo-cli reads that metadata and uses it to copy your photos into a new, organized folder hierarchy — leaving your original files untouched.

photo-cli extracts two key pieces of information from each photo:

- **When** — the exact date and time the photo was taken, recorded automatically by your camera or phone
- **Where** — the GPS coordinates embedded in the file, which photo-cli resolves to a human-readable address (country, city, town, neighbourhood, street) using a reverse geocode provider

The result is a folder of photos with structured, meaningful names like `2024.03.15_14.22.01-France-Paris.jpg` instead of `IMG_4823.jpg`.

## How it works

photo-cli follows a straightforward pipeline for every command you run:

1. **Scan** — gather all photo paths in the source folder, including subfolders
2. **Extract** — read EXIF data from each file to get the taken date and GPS coordinates
3. **Reverse geocode** — send each coordinate to your chosen provider to retrieve a human-readable address
4. **Copy** — write photos to the output folder using the naming and folder strategy you selected
5. **Report** — generate a CSV file with all extracted metadata so you can verify results or import into Google Maps and Google Earth

Your source folder is never modified. photo-cli always writes to a separate output folder.

#### What happened? How is it processed?

This archive process runs as a single command:

<CodeGroup>
```bash Long form
photo-cli archive \
  --input [relative|full folder path] \
  --output [relative|full folder path] \
  --album-type DateRange \
  --album-name My-Album \
  --auto-reverse-geocode-album \
  --expected-day-range 7300 \
  --delete-on-source \
  --reverse-geocode OpenStreetMapFoundation \
  --openstreetmap-properties country city
```

```bash Short form
photo-cli archive -i [relative|full folder path] -o [relative|full folder path] -y 2 -a My-Album -s -w 7300 -f -e 2 -r country city
```
</CodeGroup>

#### Step by step `photo-cli archive` process

1. Gather all photo paths in the source folder within subfolders.
2. Gather all photo companion files (if there are any) — files used for storing metadata, edits, or RAW versions saved alongside the photo (for example, iPhone Live Photos store a short `mov` clip with the same name).
3. Extract EXIF data — taken date and coordinates — from each photo. As a third-party reverse geocode provider is selected, photo-cli builds an address with `OpenStreetMap` using the given administrative levels (`city town`) for each photo.
4. Because `expected-day-range` is given, photo-cli validates that all photos fall within the expected day range. If any photo is outside the range, the process won't start. This argument is optional.
5. Photos missing coordinate information or with reverse geocode properties missing are listed as warnings.
6. With the `verify` argument, photo-cli calculates SHA1 file hashes and confirms all photos copied correctly by comparing hashes against the originals.
7. In the output folder, photos are placed under `/[year]/[month]/[day]/`. For example: `/2008/07/16/`.
8. Photo file names are formatted as `yyyy.MM.dd_HH.mm.ss-{sha1-hash-of-file}.{extension}`. For example: `2008.07.16_11.33.20-90d835861e1aa3c829e3ab28a7f01ec3a090f664.jpg` (originally `IMG_2371.jpg`). Companion files keep their original extension.
9. Duplicate photos with different names (`DSC_1770.JPG`, `DSC_1770_(same).JPG`) are detected by file hash. Only one is archived as `2008/10/22/2008.10.22_17.00.07-a0ab699f5f99fce8ff49163e87c7590c2c9a66eb.jpg`, and a warning is logged with the duplicate paths.
10. Photos without a taken date (e.g. `Spain Journey/IMG_5397.jpg`) are copied to a `no-photo-taken-date` folder and named only with their SHA1 hash: `cf756397cc3ca81b2650c8801fd64e172504015a.jpg`.
11. After copying, photo-cli verifies all files by comparing SHA1 hashes — guaranteeing no corruption from disk operation failures.
12. Taken dates and addresses are stored in a local SQLite database (`photo-cli.sqlite3`) at the top of the output folder so you can later query photos by metadata.
13. The `album-name` argument creates a `DateRange` album named `My-Album` in the database, spanning the earliest and latest photo dates.
14. The `auto-reverse-geocode-album` argument creates an album per reverse geocode level — for example `Firenze`, `Venezia`, `Italia`, `United Kingdom`.
15. The `delete-on-source` argument removes all source photos, companion files, and empty directories after a successful archive.
16. Final statistics are printed to the console.

#### Step by step `photo-cli copy` process

1. Gather all photo paths in the source folder within subfolders.
2. Extract EXIF data — taken date and coordinate — from each photo.
3. Because the file naming style is `DateTimeWithSecondsAddress` (which contains an address), photo-cli builds the address with `OpenStreetMap` using levels `city town suburb` for each photo.
4. Because the folder process type is `SubFoldersPreserveFolderHierarchy`, the output folder mirrors the original folder hierarchy.
5. The folder append type is `DayRange` and the folder append location is `Prefix`, so each output folder name is prefixed with the earliest and latest photo dates inside it. For example: `2005.12.14-2008.10.22-Italy album` (originally `Italy album`).
6. Each file is named with the photo taken date and the address. For example: `2012.06.22_19.52.31-United Kingdom-Ascot-Sunninghill and Ascot.jpg` (originally `GOPR6742.jpg`).
7. The no-taken-date and no-coordinate actions are both `InSubFolder`, so photos missing that EXIF data are placed into a sub-folder under the original folder hierarchy. For example: `/Italy album/no-address/IMG_2371.jpg` and `/Spain Journey/no-address-and-no-photo-taken-date/IMG_5397.jpg`.
8. The `verify` flag computes and compares SHA1 hashes after copy — guaranteeing no corruption.
9. A `photo-cli-report.csv` is created in the output, containing every photo's metadata.

## How it's done

photo-cli works by extracting [Exchangeable image file format (EXIF)](https://en.wikipedia.org/wiki/Exif) data stored in each of your photographs.

### When

[The photograph's taken date](https://en.wikipedia.org/wiki/Exif#Background) is used to determine when the photo was taken. Most cameras and cell phones save this data without any special setting.

### Where

[The photograph's coordinate data](https://en.wikipedia.org/wiki/Exif#Geolocation) is sent to the selected third-party reverse geocode provider to [build an address](/reverse-geocoding/building-address).

Most cameras and cell phones have a [GPS](https://en.wikipedia.org/wiki/Global_Positioning_System) receiver — you just need to make sure that a setting such as `Save GPS location` is enabled.

## Supported photo types

With the default settings, `jpg`, `jpeg`, `heic`, and `png` photo files are supported. Internally, photo-cli uses the [MetadataExtractor](https://www.nuget.org/packages/MetadataExtractor/) package to read EXIF data, so you can extend the supported formats to any [MetadataExtractor-supported file](https://github.com/drewnoakes/metadata-extractor-dotnet?tab=readme-ov-file#features) using the [settings command](/commands/settings):

```bash
photo-cli settings -k SupportedExtensions -v jpg,jpeg,heic,png,tiff
```

See [Supported formats](/configuration/supported-formats) for the full list and configuration details.

## Processing companion files

Companion files sharing the same name as your main photo files are also processed alongside the photo. The default companion extension is `mov`, commonly produced by [iPhone Live Photos](https://support.apple.com/en-us/104966) as a short video clip stored next to the photo.

You can extend the companion extension list with the [settings command](/commands/settings):

```bash
photo-cli settings -k CompanionExtensions -v mov,xmp,aae
```

See [Companion files](/configuration/companion-files) for details.

## MCP server for AI assistants

photo-cli can act as a [Model Context Protocol](https://modelcontextprotocol.io/) stdio server, exposing your archived photo database to AI assistants like Claude or Visual Studio Code so they can query your photos conversationally — by date, location, album, or proximity to a GPS coordinate.

```bash
photo-cli mcp --input /path/to/archive-folder
```

The server exposes tools such as `search_photos`, `find_near_location`, `list_photos_by_date_range`, `list_albums`, and `get_statistics`. See [photo-cli mcp](/commands/mcp) for the full list of tools and setup instructions for Claude Code, Claude Desktop, and VS Code.
